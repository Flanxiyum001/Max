# M14 — optional local-only semantic memory

An owner-opt-in pgvector adapter and separately provisioned SQL schema add a
384-dimensional HNSW index over reviewed memories. Upsert requires exact
owner/scope, an **approved** non-expired record and its current revision under
a database lock. Search rejoins the canonical max_memories table and excludes
stale revisions, pending/rejected/expired facts and cross-scope hits. Hard deletion
cascades to embeddings.

This is NOT enabled by Alembic, startup, API, model gateway or background jobs.
The existing PostgreSQL CI service has no pgvector extension; unit tests cover
vector and backend input guards only. A pgvector-enabled PostgreSQL integration
run, restore and deletion/revocation tests are REQUIRED before operational use.

Security preconditions: explicit reviewed **local** 384-dimensional embedding
model and pinned model/version; classification and consent; encrypted data and
backups; restricted DB roles; no cloud embeddings without separate owner opt-in;
embedding cache/backup deletion lifecycle and extension privilege review.
Never accept vectors generated by untrusted tools as owner memories.

After owner-approved deployment of sql/optional_pgvector_384.sql and a trusted
offline backfill process, the internal SemanticMemoryIndex can upsert and search.
It does not call or download a model, run a network request or forward content.
